1. Problem Statement & Research Objectives

Why traditional database systems fail on nationwide transportation datasets
Academic Context

The Core Transportation Problem

  • Severe Seasonal Surges: Summer vacations and major festivals (Diwali, Chhath, Durga Puja) cause massive passenger waitlists and uncontrolled overcrowding.
  • Capacity Misallocation: High-density corridors experience seat shortages while secondary corridors run with empty coaches, wasting energy and rolling stock.
  • Junction Delay Cascading: Knock-on delays propagate across shared railway junctions without automated root-cause severity analysis.

Why Big Data Technologies (BDT)?

  • Relational Database Limitations: Traditional SQL queries (`GROUP BY` over millions of rows) suffer memory locks and lack in-memory distributed scalability.
  • Google Colab Prohibited: College academic guidelines mandate building an enterprise, standalone Java application running locally on Windows.
  • Our Solution: A 100% Java + Apache Spark 3.5.1 platform performing sub-second in-memory transformations and machine learning demand forecasting.

6. Spark MLlib Demand Forecasting Pipeline

Random Forest regression with strict chronological train/test separation
Module 4: ML

Machine Learning Pipeline

  • Algorithm: Apache Spark MLlib `RandomForestRegressor` (25 decision trees, max depth 5).
  • Feature Vector Assembler: 
    [dow, month, dom, weekend_flag, distance_km, capacity]
  • Strict Chronological Split: Earliest 80% records used for training; subsequent 20% held out for evaluation.
  • Zero Data Leakage: Eliminates future-to-past temporal contamination.

Evaluation Metrics & Projections

  • MAE (Mean Absolute Error): ~30–40 passengers on 1,500-seat rakes.
  • $R^2$ Score (Goodness of Fit): $R^2 > 0.88$ on high-volume routes.
  • Triple-Curve Visualization (620px):
    • Blue = Ground truth historical demand.
    • Purple = MLlib test predictions on held-out dates.
    • Emerald = Upcoming 7-day future projections.
  • 7-Day Advisory: Recommends coach rake sizing (14–16 coaches).
Speaker Notes: "Module 4 implements true machine learning with Spark MLlib. Unlike naive random splits, we order data chronologically to guarantee zero data leakage. Our Random Forest model achieves an R² above 0.88."
